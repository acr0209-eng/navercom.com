# 내 정보 영수증 — 권리 행사 마찰 지수(PFI) A/B 비교 실험

NAVER Privacy Challenge 제안서 **"내 정보 영수증: 3클릭 접점형(In-context) 개인정보 통제 레이어"**
의 검증 실험(제안서 4장) 구현체입니다. 참가자가 두 가지 인터페이스에서 동일한 프라이버시
과업 5종을 수행하면 클릭 수·경로 뎁스·소요 시간·성공 여부·SEQ가 자동 기록되고,
**PFI(Privacy Friction Index)** 로 합성되어 전후 비교됩니다.

- **조건 A — 현행 목적지형(destination)**: 설정 메뉴를 찾아가는 현행 방식 시뮬레이션.
  깊은 뎁스, 제각각인 메뉴 명칭, 만류형 확인 문구, 완료 피드백 부재를 재현.
- **조건 B — 제안 접점형(in-context)**: 개인화 결과물(추천·광고·AI 응답)마다 ⓘ 영수증
  아이콘 → 바텀시트 → 신호 토글 → '적용됨 · 실행 취소' 스낵바의 3클릭 흐름.

## 실행 방법

빌드 없는 정적 사이트입니다. ES 모듈을 쓰므로 로컬 서버로 열어야 합니다.

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

- `index.html` — 실험 러너 (참가자 등록 → 과업 10회 → 완료). 데모 모드로 측정 없이 둘러보기 가능.
- `results.html` — 결과 대시보드 (지표 표, PFI 비교, CSV/JSON 내보내기, 데이터 초기화).

GitHub Pages 등 정적 호스팅에 그대로 배포할 수 있습니다. 데이터는 서버 전송 없이
브라우저 localStorage(`pfi_sessions_v1`)에만 저장됩니다.

## 실험 프로토콜

1. 참가자 ID 입력, 인터페이스 순서 선택(기본: 세션 수 기준 A→B / B→A 자동 교대 — 카운터밸런싱).
2. 과업 5종(아래) × 2조건 = 10 시행. 시행마다 시뮬레이션 상태가 초기화됩니다.
3. 과업별 제한 시간 180초(`js/config.js`), 초과 또는 '과업 포기' 시 실패로 기록.
4. 과업 직후 SEQ(Single Ease Question) 1문항: 1 = 매우 쉬웠다 … 7 = 매우 어려웠다.
5. 시행마다 즉시 저장되므로 중도 이탈해도 그때까지의 데이터는 남습니다.

### 과업 5종 (제안서 4.2절)

| # | 과업 | 조건 B 최단 경로 | 조건 A 최단 경로 |
|---|---|---|---|
| t1 | '손목 보호대' 검색어 추천 차단 | 추천 카드 ⓘ → 검색어 신호 토글 OFF (2클릭) | 메뉴→설정→서비스 설정→콘텐츠 개인화→관심 키워드→삭제→확인 (7클릭) |
| t2 | 맞춤형 광고 수신 중지 | 광고 ⓘ → 맞춤형 광고 토글 OFF (2클릭) | 메뉴→설정→개인정보 보호→광고 설정→맞춤형 광고→토글→확인 (7클릭) |
| t3 | '최근 본 상품' 기록 삭제 | 최근 본 상품 ⓘ → 기록 삭제 (2클릭) | 쇼핑→MY쇼핑→최근 본 상품→편집→전체 삭제→확인 (6클릭) |
| t4 | 개인정보 이용내역 열람 | 아무 영수증 ⓘ → 전체 이용내역 보기 (2클릭) | 메뉴→설정→개인정보 보호→프라이버시 센터→이용내역 조회 (5클릭) |
| t5 | AI 학습 활용 제외 신청 | AI 브리핑 ⓘ → AI 학습 토글 OFF (2클릭) | 메뉴→설정→AI 서비스→AI 데이터 관리→제외 신청→신청하기→확인 (7클릭) |

## 측정 규칙

- **클릭 수**: 시뮬레이션 프레임 안의 모든 클릭(배경 오조작 포함). 최소 경로가 아니라
  실제 상호작용 비용을 잰다.
- **경로 뎁스**: 화면(페이지) 전환 수. 바텀시트·확인 대화상자는 페이지 이동이 없으므로
  뎁스로 세지 않는다(클릭으로는 센다). 과업 시작 시의 초기 피드 렌더는 제외.
- **소요 시간**: '과업 시작' 클릭부터 성공 판정(또는 실패)까지. 성공 직후의 피드백
  노출 시간(1.2초)은 포함되지 않는다.
- **성공 판정**: 과업별 상태 프레디킷(`js/tasks.js`)이 충족되는 순간 자동 완료.
  두 조건에 동일한 프레디킷을 적용한다.

## PFI 공식

```
PFI = 100 × Σ wᵢ × normᵢ          (0~100, 낮을수록 권리 행사가 쉽다)

norm_clicks   = min(클릭 수 / 15, 1)
norm_screens  = min(뎁스 / 10, 1)
norm_duration = min(소요 시간(초) / 180, 1)
norm_fail     = 성공 0 / 실패 1
norm_seq      = (SEQ − 1) / 6

가중치 wᵢ = 각 0.2 (균등)
```

캡·가중치는 `js/config.js`에서 조정합니다. 소규모 패널(과업당 10명 내외)에서는
z-표준화가 불안정하므로 **고정 기준(캡) 정규화**를 채택했습니다. 성공률 자체는
과업×조건 그룹 단위로 별도 집계하고, 시행 단위 PFI에는 실패 여부(0/1)로 반영합니다.

## 데이터 스키마

`results.html`에서 CSV/JSON으로 내려받을 수 있습니다.

- **시행 CSV** (`pfi_trials.csv`): `participantId, sessionId, order, condition, taskId,
  clicks, screens, durationSec, success, result, seq, pfi`
- **이벤트 CSV** (`pfi_events.csv`): `participantId, condition, taskId, type(click|screen|toggle|task_start|task_success|task_fail), screen, target, value, tMs`
- **JSON** (`pfi_raw.json`): 세션 전체 원자료.

| 3.4 대칭성 원칙 | 켜기·끄기 동일 토글/단계, B에는 만류 문구 없음(A의 만류형 대화상자와 대조) |

| 4.3 KPI(PFI 50% 감소) | `results.html` 요약 타일·과업별 감소율 표시 |
| 5장 걸림돌 '기존 기능 충돌' | 영수증=현장 진입점, 프라이버시 센터=이력 허브의 역할 분담을 시뮬레이션에 반영 |

## 파일 구조

```
index.html            실험 러너
results.html          결과 대시보드
css/style.css         시뮬레이션·대시보드 스타일
js/config.js          제한 시간·PFI 캡·가중치 설정
js/app.js             실험 흐름 제어(안내→시행→SEQ→완료)
js/tasks.js           과업 5종 정의 + 성공 판정
js/sim-state.js       시뮬레이션 상태(신호·최근 본 상품·이력)
js/logger.js          클릭·화면전환·시간 기록
js/screens-common.js  Sim 엔진 + 공용 피드 화면
js/screens-baseline.js  조건 A: 목적지형 설정 메뉴 트리
js/screens-receipt.js   조건 B: 영수증 바텀시트·토글·스낵바
js/pfi.js             지표 집계 + PFI 산출
js/export.js          CSV/JSON 내보내기
js/results.js         대시보드 렌더링
```
